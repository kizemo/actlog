> **✅ 本轮已全部修完并验证通过（`E2E_EXIT=0`，4 例全绿）。**

### 4.1 当时的现象与真实根因

`apps/desktop/test/p1_e2e_test.dart`（4 个用例）曾表现为「3 个用例挂死」。

> **那是误判。** 真相是：4 个用例都在 **2 秒内**抛异常失败，
> 但 `flutter test` 报错后继续跑剩余用例、输出被缓冲，看起来像挂死；
> 400s 命令上限是被 3×90s 单测超时耗尽的，不是死锁。

**根因（两个，都已修）**：

1. **真实产品缺陷**：`review_section.dart:58` 与 `mood_section.dart:41` 的 `dispose()`
   里调用 `_persist()` → `ref.read(repositoriesProvider)`。
   Riverpod 在 widget 卸载时抛
   `Bad state: Using "ref" when a widget is about to or has been unmounted is unsafe.`
   → **P1-1 / P1-5 / P1-6 三个用例全被它打挂**（不只是测试问题，真实运行时关窗也会炸）。

   修法：把仓储实例在 `build()` 里捕获进 `_repo` 字段（`_repo ??= ref.read(...)`），
   `dispose()` 只用字段，不再读 `ref`；落库逻辑抽成 `_persistTo(DayLogRepository repo, String logId)`。

2. **测试断言歧义**：`find.text('写完 P1 今日页')` 同时命中**输入框里的文本**和**列表项**；
   即便限定在 `ListView` 内，**站会区块的「今日优先」也会列出今天的计划条目** ⇒ 仍是 2 个。

   修法：新增 `_inPlanBlock(text)` 辅助函数，用
   `find.descendant(of: find.ancestor(of: find.text('今日计划'), matching: find.byType(SectionCard)), matching: find.text(text))`
   把范围钉死在「今日计划」这张卡片里。需 import `package:practilog/src/widgets/section_card.dart`。

3. **收尾噪声**：`A Timer is still pending even after the widget tree was disposed.`
   —— drift 的 `StreamQueryStore.markAsClosed` 排的 0 长度 timer。
   已加 `_flushTimers(tester)`，**必须写在用例体内**（见 §4.3 的表）。

## 十一、跨日翻车防线（重要）

本项目有两处**语义上是"今天"但代码里写死了日期**的地方，都已修：

| 位置 | 原写法 | 现写法 | 为什么必须这样 |
|---|---|---|---|
| `packages/core_data/test/repositories_test.dart` | `const String _today = '2026-11-06'` | `final String _today = today()` | `HabitRepository.create` 的 `startDate` 默认就是 `today()`，而 `listScheduledFor` 判定 `startDate <= 查询日`。写死日期 ⇒ 跨日后新建习惯不进排程 |
| 同文件 3 处 | `'2026-11-07'` / `'2026-11-08'` | `shiftIsoDate(_today, 1)` / `shiftIsoDate(_today, 2)` | 写死「今天+1」「今天+2」，明天就退化成「昨天」「前天」，语义漂移 |
| `apps/desktop/test/p1_e2e_test.dart` | `const _date = '2026-11-07'` | 保持写死 | **有意为之**：e2e 要的是「一条固定的、可造靶子的当天」，与真实日历无关 |

**判定规则**：
- 日期字面量出现在**显式传参**位置（测格式、测约束、测排序）⇒ 安全，保留。
- 日期字面量出现在**「隐含依赖真实当天」**位置（如 `create` 的默认 `startDate`）⇒ 必须改成 `today()` 派生。

已扫描确认安全的：`support_test.dart`、`standup_test.dart`（纯函数，输入全显式）、
`core_db/constraints_test.dart`、`core_db/oplog_writer_test.dart`、`core_domain/domain_test.dart`。

## 十三、根因档案：nativeapi 的 `preventClose` 拦不住 raw `WM_CLOSE`（第四次会话）

**现象**：插件层 `windowManager.setPreventClose(true)` 已经开了，Dart 侧自己调 `windowManager.close()`
确实被取消（自检里 `preventClose=true onWindowClose=true`），但**用户点窗口右上角的关闭按钮，
进程照样退出** —— 窗口消失、托盘图标也没了。

**真身**：`preventClose` 只覆盖**插件自己发起的** close 调用。Windows 关闭按钮发的是 raw `WM_CLOSE`：

```
用户点 X
  → WM_CLOSE
  → Flutter 模板的 win32_window.cpp 没有任何 WM_CLOSE 分支
  → DefWindowProc(WM_CLOSE) ⇒ DestroyWindow
  → WM_DESTROY ⇒ PostQuitMessage(0)      ← win32_window.cpp 的 quit_on_close_ 路径
  → 消息循环结束 ⇒ 进程退出
```

`flutter_controller_->HandleTopLevelWindowProc` 会被调用，但插件钩子只对**插件自己发的 close** 有反应，
raw `WM_CLOSE` 它不认。

**修法（落在 runner 层）**：`apps/desktop/windows/runner/flutter_window.cpp` 的 `MessageHandler`
在**插件钩子之前**拦截：

```cpp
if (message == WM_CLOSE && hide_on_close_) {
  ShowWindow(hwnd, SW_HIDE);
  return 0;   // 不销毁窗口、不退出进程
}
```

`hide_on_close_` 由 Dart 通过 `MethodChannel("practilog/window")` 的 `setHideOnClose` 打开 ——
**必须在托盘就绪之后才开**（托盘建不起来时不能拦截关窗，否则进程变成既关不掉又看不见的僵尸）。

**验收**：`tools/verify/exe_smoke.ps1` 用 `PostMessage(WM_CLOSE)` 模拟点 X，断言
「进程仍存活」+「窗口不可见」两项都成立。

## 十四、根因档案：Flutter Windows C++ 客户端 API 的两个坑（第四次会话）

1. **`flutter_controller_->engine()->binary_messenger()` 不存在**。
   `FlutterEngine` 的访问器叫 **`messenger()`**（返回 `BinaryMessenger*`）。
   误用会报 `error C2039: "binary_messenger": 不是 "flutter::FlutterEngine" 的成员`。
2. **`flutter::MethodChannel` 的构造函数要三个参数**：
   `MethodChannel(BinaryMessenger* messenger, const std::string& name, const MethodCodec<T>* codec)`。
   只传 messenger + name 会报
   `error C2661: "flutter::MethodChannel<flutter::EncodableValue>::MethodChannel": 没有重载函数接受 2 个参数`。
   正确写法：`&flutter::StandardMethodCodec::GetInstance()` 作第三个参数。

**同类坑（同一批踩到，值得一起记）**：

- **PowerShell 调 `.bat` 拿不到退出码与输出**：用 `& $flutter ... *>&1 | Out-File` 时，
  退出码不可靠、输出经常是空文件，断言还会因 `System.Object[] → Boolean` 转换错误整段中断。
  **改用 `Start-Process` + `-RedirectStandardOutput/-RedirectStandardError` + `-Wait` + `$p.ExitCode`**。
- **ATL 反向验证的失败形态取决于增量构建状态**：全新构建是 **C1083**（编译期找不到 `atlbase.h`）；
  插件 obj 还在旧产物里时，编译被跳过、只走到链接，报 **LNK1104**（找不到 `atls.lib`）。
  两者都表示「没有借用就没有可用 ATL」，断言应同时接受。
- **`use_of_void_result`**：`Completer<void>` 上写 `.then((value) => value != null)` 会报；
  改用 `Completer<bool>` + `onTimeout: () => false`。
