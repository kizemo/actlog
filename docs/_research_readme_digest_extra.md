## journiv/journiv-app

**一句话定位（忠于 README）**
自托管的私密日记应用（self-hosted private journal），提供完整的日记能力：心情追踪、提示词式日记、媒体上传、统计分析、进阶搜索，配简洁极简的界面。

**平台**
- Web 端为主：生产容器在同一个 FastAPI origin 与端口下同时提供编译后的前端与 API（`/` React 前端为主、`/legacy/` Flutter 前端为临时旧版、`/api/v1/*` FastAPI API、`/pub/*` 公开发布路由、`/docs` 与 `/openapi.json`）。
- 通过浏览器访问任意设备（README 演示视频标题含 "Web Tab Mobile"），未提供原生移动/桌面安装包。
- 部署方式：Docker / Docker Compose，另提供 PikaPods、Easypanel 一键部署按钮与他人托管的 demo 实例。

**技术栈与本地存储**
- 后端 FastAPI（Python），前端 React（V2）与 Flutter（旧版，暂留在 `/legacy/`）。
- 容器化部署，数据持久化在卷 `journiv_data:/data`；README 未说明具体数据库类型。
- 异步任务依赖 Redis/Valkey broker + Celery worker（媒体处理、导入导出作业）。
- **非 local-first**：必须自建服务端运行；单条 `docker run` 只是最小版。
- 有独立的 AI 辅助开发披露：明确说明「AI 只用于开发，运行时不依赖 LLM 服务，开发过程也不会把日记内容发送给 AI 供应商」。

**同步机制**
- 自建服务端（单实例服务端 + `/data` 卷），README 未提供 E2EE、WebDAV 或其他同步通道。
- README 强调「保持数据向后兼容，但破坏性变更仍可能发生，请定期备份」。

**核心功能清单（README 实际写出）**
1. 日记记录（含心情追踪 mood tracking）。
2. 提示词式日记（prompt-based journaling）。
3. 媒体上传（图片、视频、音频）。
4. 统计分析（analytics）。
5. 进阶搜索（advanced search）。
6. 公开发布路由 `/pub/*`（Public publishing routes）。
7. FastAPI API + OpenAPI schema + 可开关的 `/docs`。
8. Docker 最小版与完整 Compose 版两套安装形态；PikaPods / Easypanel 部署模板；公共 demo 账号。
9. 支持的管理与社区渠道：GitHub Issues、Discussions、Email、Discord、Reddit。

**最值得借鉴的具体机制**
1. **单 origin 多前端并存 + 精确退役旧 Service Worker**：用 `/flutter_service_worker.js` 这个「退役 worker」只替换旧根 Flutter worker、只清理 `flutter-app-*` 缓存、注销自身后 reload 受控窗口；React 侧只针对该精确根注册做一次性检查，其它 SW 注册一概不碰，从而为将来 React PWA 留出路径。这是「前端迁移不破坏用户缓存与离线能力」的完整做法。
2. **按依赖把重功能显式降级并明确告知**：最小 `docker run` 允许上传媒体但图片/视频/音频停留在 Processing，且导入导出作业同样需要 worker；README 用 NOTE 直接点明「这些功能需用完整 Compose 文件」。这种「同一产品两种部署形态 + 明确能力边界」的分级很适合行动日志应用的云/本地双形态。

**README 自述的局限**
- 处于 beta、持续开发中；虽力求向后兼容，破坏性变更仍可能发生，**必须定期备份**。
- 单 `docker run` 的最小形态下媒体停留在 Processing，导入/导出不可用（需 Redis/Valkey + Celery worker）。
- HTTP + `ALLOW_INSECURE_COOKIE_AUTH_OVER_HTTP=true` 仅为隔离可信局域网，密码与 refresh cookie 会被同网段嗅探；公网必须 `DOMAIN_SCHEME=https`。
- Flutter 旧版前端仅临时保留于 `/legacy/`，未来版本可能移除。
- 个人业余项目开发，AI 辅助开发程度较高（作者声明后端按代码级审查，React 侧以 UI 手测为主而非逐行审查）。

## memex-lab/memex

**一句话定位（忠于 README）**
开源、local-first 的 AI 日记应用（iOS/Android）：「不是用来写每日条目的，而是用来捕捉生活碎片、再让 AI 整理它们」。

**平台**
- iOS（App Store，含中国区）与 Android（Google Play，早期可下 APK），Flutter 实现。
- README 未提桌面端或 Web 端。

**技术栈与本地存储**
- Flutter（Dart ≥ 3.6）+ Drift（SQLite）+ Provider/MVVM + `dart_agent_core` 智能体框架；l10n 覆盖 17 种语言。
- **local-first**：记录、卡片、知识库全部留在设备（文件系统 + SQLite）；没有 Memex 服务器存储日记。AI 组织后的记录最终沉淀为一组互相链接的 Markdown 文件。
- 自带 LLM（BYO provider）：prompt 从手机直连 OpenAI / Claude / Gemini / DeepSeek 等，Memex 不经手数据；可选的 Memex AI 服务「只代理模型请求、不存储日记」。支持 Ollama 本地模型。
- 存储位置可选 iCloud Drive / 设备自定义目录 / App 存储。

**同步机制**
- 无内建多端同步引擎（README 未描述同步/实时协同）；提供「一键全量备份 / 恢复」+ iCloud Drive 目录 + 应用内存储位。

**核心功能清单（README 实际写出）**
1. **Memex Agent 编排**：一个对话式 agent 协调专长 skills 与子 agent，覆盖时间线卡片、PKM 归档、日程更新、知识洞察、诊断、评论、记忆整理、媒体处理、陪伴对话。
2. **按记录类型自动生成最合适的卡片**：
   - 生活与生产力（task / routine / event / duration / progress）——记录待办、习惯、日程与目标；
   - 知识与媒体（article / snippet / quote / link / conversation）；
   - 人与地点（person / place，带地图预览）；
   - 数据与指标（metric / rating / transaction / spec sheet）；
   - 视觉（gallery）。
3. 自动打标签、实体抽取、交叉引用链接。
4. 可针对任意卡片或话题对话的 AI 助手。
5. **P.A.R.A** 知识组织（Projects / Areas / Resources / Archives）。
6. **洞察卡片**：图表类（趋势、柱状、雷达、气泡、构成、进度环）、叙事类（高亮、对比、摘要、周期回顾）、时空类（地图、路线、时间线）、画廊类。
7. **AI 伴侣**：创建有个性的 AI 角色；自动评论新时间线卡片；1v1 对话且能记住卡片与知识中的生活上下文；跨评论与对话场景的长期记忆；兼容 SillyTavern（导入 V2 JSON + PNG 角色卡，含 persona / world book / 示例对话）。
8. **纯文本与数据自由**：AI 整理后所有记录沉淀为互相链接的 Markdown 文件；一键导出标准 Markdown 迁移到任意笔记应用。
9. 隐私：本地存储（文件系统 + SQLite）、生物识别应用锁、无云依赖。
10. 存储与备份：iCloud Drive / 自定义目录 / App 存储；一键全量备份与恢复。
11. 多 LLM 供应商支持（Gemini、OpenAI、ChatGPT OAuth、Claude、Bedrock、Memex AI、Kimi、Qwen、Doubao、GLM、DeepSeek、MiniMax、MiMo、OpenRouter、Ollama）。
12. **自定义 Agent 系统**：自由创建 agent、事件驱动触发（保存新时间线卡片后 / 发表评论后 / 卡片 UI 配置变化 / 本地数据变化）、每 agent 独立模型、自定义 system prompt、基于开放 Agent Skills 标准的 `SKILL.md`、独立工作目录（文件读写限定在该目录）、技能内可执行 JavaScript（含 `fetch()`）、`dependsOn` 智能体依赖链、同步/异步执行模式、异步任务自动重试（可配最大重试次数）。
13. 位置上下文：可附加城市/区/街道，可选 OpenStreetMap/Nominatim（免 key）或高德（需 key），只用设备 GPS 不用 IP 定位。

**最值得借鉴的具体机制**
1. **「碎片 → 分类卡片 + UI 配置」的结构化流水线**：用户只扔碎片（文字/图片/语音/分享文件），由 super agent 分派给专长 skill（timeline_card → 卡片 YAML + UI config；pkm → P.A.R.A Markdown；schedule → 日程状态；knowledge_insight → 跨记录洞察卡），后台再跑角色评论、长期记忆整理、事件驱动自定义 agent。卡片类型里直接把 **task / routine / event / duration / progress** 列为「生活与生产力」类，等于给行动日志预置了字段语义。
2. **BYO 模型 + 「服务端只代理不存储」的隐私设计**：prompt 从设备直连用户自选 provider（也可 Ollama 本地），可选托管服务明确声明只转发模型请求；再叠加 `SKILL.md` 开放标准、每 agent 独立工作目录与 `dependsOn` 依赖链 + 异步自动重试，构成一套可扩展且不出设备的数据面。
3. **Markdown 作为长期归档底座**：AI 整理后的记录最终落成互相链接的 Markdown 档案，理由是纯文本才能持续被更强模型重新读取——这让「AI 回顾」天然建立在可被重新解析的文件之上，而不是锁死在数据库里。

**README 自述的局限**
- AI 功能**必须有配置好的模型服务**才能用（首次启动需选 provider 并填 API key / base URL 或 OAuth）。
- 部分 OAuth 接入（Google Gemini、ChatGPT）标注为非官方，「自担风险」。
- 位置上下文依赖设备 GPS 与第三方逆地理编码（高德需 key）。
- Roadmap 中多项尚未实现（定时洞察刷新、Agent Soul、定制知识方法论与标签规则、可扩展数据源与触发条件、扩展市场与插件架构），「打开 issue 不保证被实现」。
- 视频与文件附件流程仍待增强（Roadmap 首条）。

## CikeSeven/jotsy

**一句话定位（忠于 README）**
「一本只属于你的本地日记」——免费、开源、无广告、无需注册，数据只存在用户自己的设备里；打开就能写的心情/灵感/三餐/旅行记录工具，附带照片、视频与录音。

**平台**
- Android 7.0+（arm64-v8a / armeabi-v7a / x86_64）、Windows 10+ x64（安装版与便携版）、Linux x64（GTK 3）。**明确暂无 iOS 版**。
- README 未指明实现框架（仅说明数据落在应用私有目录的 SQLite 数据库）。

**技术栈与本地存储**
- SQLite（应用私有目录）+ 同目录存放图片/录音/视频/附件；设置存本机；Material 3 Expressive 设计语言。
- **完全 local-first**：没有账号体系，也没有自己的服务器。
- 联网场景仅四类：自动取地点与天气（高德地图、和风天气）、网盘备份/恢复、检查与下载更新（GitHub Releases 及镜像）、导入云端笔记（对应厂商官网）。
- 内置应用内更新：多条国内镜像线路自动选最快、断点续传、安装前校验文件校验值与应用签名。

**同步机制**
- 无实时多端同步；提供网盘备份通道：WebDAV（坚果云、NAS、Alist 等）、S3 兼容对象存储（阿里云 OSS、腾讯云 COS、R2 等）、Google Drive / OneDrive / Dropbox / 百度网盘 / 阿里云盘，可从远端直接恢复。
- 本地完整备份为一个 ZIP（含日记、标签、纪念日、设置与全部媒体），可设密码用 **AES-256** 加密。

**核心功能清单（README 实际写出）**
- **写作**：23 种编辑工具（标题、粗斜下划删除线、文字与背景色、有序/无序/待办清单、引用、代码块、链接、插入当前时间，工具栏顺序与显隐可自定义）；一次插入多图/多视频、任意类型附件、录音支持暂停继续且回放可拖波形、长截图自动折叠可滚动阅读；自动定位取天气与手动填写、地址精度可选城市/区县/街道/门牌号；10 个心情 Emoji（可替换）与 5 档精力值、发表时间可改；「补写有照片」——给过去某天补写时列出当天拍摄的照片，勾选插入或设为封面（须授权后读取相册、原图不改动）；新建自动存草稿、编辑自动保存；8 个内置模板（每日记录、晨间日记、晚间复盘、感恩日记、每日一问、周回顾、情绪梳理、读书笔记）+ 自建 + 一篇存为模板 + 模板码分享。
- **模板机制细节**：新建空白日记时标题下按时段推荐模板，一点套用，也能按时间段自动套用；`{{日期}}`、`{{农历}}`、`{{今日一问}}` 等变量按日记日期自动填充，并顺带设好标签、心情与时间胶囊。
- **浏览阅读**：列表 / 瀑布流两种布局，按更新时间、发表时间或标题排序；标签筛选（记住上次筛选）与搜索叠加；日记本（一篇可入多本、移出不删、分章节与手动目录、写作目标与统计、整本导出带扉页目录的 PDF/Word/网页/Markdown/纯文本、智能日记本按标签/心情/日期自动收录、可整体隐藏、可上锁并验证身份）；置顶、归档、多选批量、回收站与立即撤销；详情页左右滑动按进入时列表顺序切上下篇；字数统计规则为汉字按字、英文数字按词，详情页可看段落数、图片数与预计阅读时间。
- **外观**：日记卡片 8 种内置风格、详情页 8 种预设，卡片与详情页各可保存 12 份自定义样式并用「样式码」分享/导入；正文字体内置 HarmonyOS Sans 或跟随系统或导入 TTF/OTF/TTC，字号行距字距段距可调且编辑/阅读/发布页统一生效；10 色系 80 种主题色、明暗主题、界面字号可调、界面支持中/英/日/俄；功能管理——日历、探索、日记本、纪念日、日记模板、时间胶囊可单独关闭，关闭后功能不再出现在任何地方但数据不丢，重开即恢复。
- **日历**：月视图与周视图显示农历、节气与节日；日历下汇总本月篇数、记录天数、字数、最常见心情、最长连续记录；法定节假日标注「休」与调休「班」；纪念日与倒数日（按公历或农历每年重复或只记一天，显示第几周年与还剩几天，可关联一篇日记并汇总历年同日日记）；日期格 5 种样式（圆点/心情/热力/照片/标签）且可按心情或标签筛选；选起点终点看区间统计，年视图按心情/篇数/字数生成全年热力图并分享为图片；长按某天可补写日记、给未来写时间胶囊或添加纪念日。
- **探索与回忆**：总记录数、连续打卡天数、本月字数；「那年今日」自动翻出往年同一天的日记；趋势与标签云（近 30 天心情、近 7 天精力、最常用标签）；媒体画廊汇集所有封面与正文图片；时间胶囊封存到解封日期才能打开。
- **数据与隐私**：应用锁（系统生物识别或设备密码）；ZIP 完整备份可设密码 AES-256 加密；恢复时选「合并」或「覆盖」，覆盖前醒目二次确认；网盘备份（WebDAV / S3 兼容 / Google Drive / OneDrive / Dropbox / 百度网盘 / 阿里云盘）与远端恢复；导出单篇/多选/按日期标签批量为 PDF、Word、Markdown（带 front matter，可导入 Obsidian）、网页、纯文本、CSV，或生成可在另一台设备合并导入的日记文件；生成长图或分享到微博/小红书/微信/朋友圈/QQ/QQ 空间。
- **搬家导入（18 款）**：日记类 Day One、Journey、Diarium、Daylio、Apple 手记、Diaro、榴莲日记；笔记类 Evernote、Google Keep、Joplin、Memos、Markdown/纯文本（Obsidian、Bear、Notion 导出等）；云端笔记类 小米/华为/OPPO/vivo/荣耀/魅族/锤子笔记、WPS 便签。
- **权限**：网络、麦克风（录音）、位置（可选）、相册图片（可选）、安装应用（应用内更新）。

**最值得借鉴的具体机制**
1. **模板变量 + 时段自动推荐/自动套用 + 模板码分享**：模板不仅存正文骨架，还用 `{{日期}}`、`{{农历}}`、`{{今日一问}}` 这类按日记日期求值的变量自动填内容，并联动设置标签、心情与时间胶囊；新建空白日记时按当前时段推荐模板，一点套用，可整体导出成「模板码」跨设备分享。这套「结构化表单模板 + 变量求值 + 可分享」正是「每日固定五项」打卡模板的现成范式。
2. **导入的三段式安全流程：预检 → 合并/覆盖二选一 → 覆盖前二次确认**：从 18 款应用导入时先预检内容，再让用户选合并或覆盖，破坏性覆盖必须二次确认；云端笔记导入则通过厂商官方网页登录，登录 Cookie 只存在本次导入的内存中、导入结束即清除、不落盘也不用于其他请求。
3. **本地优先 + 端到端可控的备份/导出矩阵**：无账号无服务器，SQLite 私有目录；备份打成单个 ZIP（日记+标签+纪念日+设置+全部媒体）并可选 AES-256 密码加密；导出 6 种格式并额外提供「可在另一台设备合并导入的日记文件」——把「多端一致性」交给用户可控的文件搬运而不是强推账号体系。

**README 自述的局限**
- **卸载应用或清除应用数据会丢数据**（FAQ 明示），只能靠定期导出备份或网盘备份兜底；桌面版则声明卸载或更新都不会删除日记——移动端与桌面端行为不一致。
- **暂无 iOS 版**。
- 功能按平台分叉：分享到指定应用、导入手机厂商与 WPS 云端笔记、补写时「这天拍的照片」、自动获取地点与天气仅手机提供；Windows/Linux 正文视频不在页内播放（转系统播放器）；**Linux 版不支持录音**（可播放）与**不支持应用锁/上锁日记本**；Linux 依赖 GStreamer 插件。
- 安装程序与 `jotsy.exe` **未做代码签名**，首次运行 SmartScreen 会报「未知发布者」，需靠 `SHA256SUMS.txt` 核对。
- 无服务器即无账号体系与实时多端同步，跨设备依赖备份中转。

## lunatask/lunatask

**一句话定位（忠于 README）**
该仓库存放 Lunatask 的发布版本；Lunatask 是一款「all-in-one」的一体化加密应用，同时具备待办清单、习惯打卡、日记、生活追踪与笔记。

**平台**
- README 未说明（无安装包、无系统要求、无桌面/移动描述）。

**技术栈与本地存储**
- README 未说明。仅有的技术性描述是定语「encrypted（加密）」，未交代加密算法、是否端到端、存储位置、数据库或文件格式。
- 是否 local-first、是否需要自建服务端：**README 未说明**。

**同步机制**
- 未说明。README 唯一相关线索是产品被称为「encrypted」，但同步方式（自建 / E2EE / WebDAV / 无）无从判断。

**核心功能清单（README 实际写出）**
1. 待办清单（to-do list）。
2. 习惯追踪（habit tracker）。
3. 日记（journaling）。
4. 生活追踪（life-tracking）。
5. 笔记（notes）。
6. 以上五项合于一个「all-in-one」加密应用。
7. 本仓库用于存放 Lunatask 的发布版本（releases）；项目官网为 lunatask.app。

**最值得借鉴的具体机制**
1. **「all-in-one 合流」的定位表达**：README 一句话就把待办、习惯、日记、生活追踪、笔记收进同一个加密壳里——对「五项管理行动日志」而言，这是最直接可借用的产品边界定义方式：五类信息不是五个应用，而是一份日志的五个维度。
2. **以「加密」作为一体化应用的头号卖点前置**：把加密放在定语位置（an all-in-one *encrypted* to-do list, habit tracker, journaling, life-tracking and notes app），而不是藏在安全章节——隐私承诺前置到产品一句话里，适合在应用商店首屏与官网首屏复用。

**README 自述的局限**
- README 极短、仅为发布仓库的存根：**没有任何安装/使用说明、没有截图、没有技术细节、没有隐私/加密说明、没有 changelog、没有贡献指南**。
- 唯一的功能信息就是那一行五合一描述；因此本节所有技术维度（平台、栈、存储、同步、加密方式）均无法从 README 得到证实，评估该项目必须依赖其官网而非本 README。

## 与主 agent 关注点的关联

以下按主 agent 的关注维度，逐项说明这 4 个项目里**有直接参考价值**与**确实缺失**的部分。缺失项不做脑补，明确标注。

### 1. 日记条目结构
- **memex（最直接）**：`life & productivity` 卡片类型被明确细分为 **task / routine / event / duration / progress**，正好对应「五项管理」的行动语义（待办、例行、事件、耗时、进度）；卡片落地形式是 **YAML + UI config**（`timeline_card` skill 输出），意味着结构化字段与展示形态分离。
- **jotsy**：条目元信息维度最全——心情 Emoji（10）、精力（5 档）、天气、地点（地址精度四级）、标签、日记本（可多归属）、发表时间可改、字数统计、待办清单编辑器；并用「模板 + 变量」把维度组合固化（`{{日期}}`、`{{农历}}`、`{{今日一问}}`，可顺带设标签/心情/时间胶囊）。
- **journiv**：仅明确 mood tracking 与 prompt-based journaling，条目字段细节在文档站（README 未展开）。
- **lunatask**：只有「journaling + life-tracking + notes」三个名词，无结构说明。

### 2. 习惯打卡
- **lunatask**：产品层面直接把 habit tracker 与 to-do list、journaling 并列，是「五合一」中最接近习惯打卡的一席。
- **jotsy**：打卡侧的量化呈现最完整——连续打卡天数、最长连续记录、近 30 天心情趋势、近 7 天精力趋势、标签云、年度热力图（按心情/篇数/字数）并可分享为图片；日历长按某天可当场补写。
- **memex**：把习惯归入卡片类型里的 `routine`，并由 schedule skill 维护日程状态。
- **journiv**：README 未提习惯/打卡。

### 3. 提醒
- **四个 README 都没有写任何提醒/通知/定时推送机制**，这一维度在本次样本中无直接参考来源。
- 最接近「按时间触发」的两个可借位点：jotsy 的**时间胶囊**（封存至解封日期才可打开）与**纪念日/倒数日**（按公历或农历每年重复、显示第几周年与剩余天数）；memex 的 Roadmap 里「Scheduled insight refresh（定时重新分析记录以发现新模式）」尚未实现，属未落地设想；journiv 的 Celery worker 队列是后端异步作业基础设施，但 README 未把它用于提醒。

### 4. AI 辅助回顾
- **memex（最强）**：洞察卡片分成四类——**图表类**（趋势/柱状/雷达/气泡/构成/进度环）、**叙事类**（高亮、对比、摘要、**periodic reviews 周期回顾**）、**时空类**（地图/路线/时间线）、**画廊类**；另有 P.A.R.A 知识组织、跨记录实体抽取与交叉引用、针对任意卡片/话题的对话助手、角色长期记忆（跨评论与 1v1 对话场景持久化）。其归档底座是 **Markdown 文件**，理由是纯文本可被更强模型反复重新读取——这使「回顾」建立在可重解析的文件层而非封闭数据库。
- **journiv**：提供 analytics 与 prompt-based journaling，即「用提示词驱动书写 + 统计分析」的轻量回顾路径；但 AI 部分 README 只声明是开发期辅助，运行时不含 LLM。
- **jotsy / lunatask**：README 无 AI 相关内容。

### 5. 隐私加密
- **jotsy**：无账号、无服务器；数据在本机应用私有目录的 SQLite；**应用锁**用系统生物识别/设备密码；备份 ZIP 可设密码并 **AES-256** 加密；网盘备份只发往用户自填服务器。
- **memex**：local-first 明确定义（记录/卡片/知识全在本机，无 Memex 服务器存日记）；**生物识别应用锁**；BYO LLM，prompt 从手机直连 provider，可选托管服务只代理不存储；支持 Ollama 本地模型。
- **journiv**：自托管 + HTTP 明文 cookie 风险告警（必须 HTTPS）+ 强调「破坏性变更可能发生，请定期备份」。
- **lunatask**：只有「encrypted」一词，**无任何可验证细节**（算法、端到端与否均未说明），只能作为「卖点前置写法」参考，不能作为加密方案参考。

### 6. 导入导出
- **jotsy（覆盖最广）**：从 **18 款**应用导入（Day One/Journey/Diarium/Daylio/Apple 手记/Diaro/榴莲日记；Evernote/Google Keep/Joplin/Memos/Markdown；小米/华为/OPPO/vivo/荣耀/魅族/锤子笔记/WPS）；导入前**预检** + **合并/覆盖**二选一 + 覆盖前二次确认；导出 PDF/Word/Markdown（带 front matter，可导 Obsidian）/网页/TXT/CSV，另有「可在另一台设备合并导入的日记文件」；生成长图与社交分享。
- **memex**：一键导出全部记录为标准 Markdown，零锁定迁移到任意笔记应用。
- **journiv**：导入/导出是作业型功能，**依赖 Celery worker**，最小部署下不可用。
- **lunatask**：README 未提导入导出。

### 7. 多端一致性
- **journiv** 是四者中唯一有服务端单一事实源的项目（FastAPI 同源多前端 + `/data` 卷），多设备访问同一实例即天然一致，但代价是必须自建服务端、且非端到端加密。
- **jotsy** 与 **memex** 都是「无账号 + 手动搬运」路线：jotsy 走 ZIP（可 AES-256）+ WebDAV/S3/主流网盘 + 可合并导入文件；memex 走 iCloud Drive/自定义目录/App 存储 + 一键全量备份恢复 + Markdown 归档。
- 两者都**没有实时同步/冲突合并引擎**，跨端一致性靠「文件 + 合并/覆盖二选一」的显式决策。
- **lunatask**：README 未说明，无法判断。

### 8. 对「五项管理行动日志」最可复用的 5 条机制（结论）
1. **碎片 → 语义化卡片的结构化管线（memex）**：把用户输入当作碎片，由单一编排 agent 分派给专长 skill，产出 **task / routine / event / duration / progress** 五类语义卡片 + YAML 字段 + UI 配置——可直接映射为「五项管理」的行动日志字段集。
2. **模板变量求值 + 时段自动套用 + 模板码分享（jotsy）**：`{{日期}}`/`{{农历}}`/`{{今日一问}}` 之类按日期求值的变量、按时段推荐并可自动套用的模板、可导出分享的「模板码」——把「每日固定五项打卡」做成可复用模板而非每次手填。
3. **打卡与回顾的量化呈现组合（jotsy + memex）**：jotsy 的连续打卡天数 / 最长连续记录 / 30 天心情与 7 天精力趋势 / 年度热力图，配合 memex 洞察卡片的**图表类（趋势、进度环）+ 叙事类（摘要、对比、周期回顾）**，构成「每日打卡 → 周/月回顾」的可落地闭环。
4. **迁移与格式 freedom（jotsy + memex）**：导入先预检、再合并/覆盖二选一、破坏性覆盖二次确认；导出多种格式并保证 Markdown（带 front matter）等纯文本底座，保证行动日志长期不被锁定、也可被未来的 AI 反复重新读取。
5. **隐私优先的本地存储 + 可控的加密备份（jotsy + memex）**：无账号无服务端、数据只在私有目录、本地生物识别应用锁、备份打包成单文件并可 AES-256 加密、备份通道由用户自选（WebDAV/S3/iCloud/Ollama 本地模型）——直接适用于敏感的行动日志数据。
