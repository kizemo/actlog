## 2. §A 设计原则（双端共享 8 条）

- **P1 一天一条闭环，不按功能切页**：时间推进即页面推进。功能是段落的归属，不是页面的划分。
- **P2 点击优先，打字兜底**：每个字段先给可选项，自由文本永远只出现在 `其他…`。目标：一次日常闭环的键盘击键数接近 0。
- **P3 选入优于新建**：计划条目从待办池 / 习惯 / 项目里选（`plan_item.source_type` + `source_id` + `source_todo_id` + 标题快照已支持），而不是重新打一遍字。
- **P4 缺什么亮什么**：页面顶部一条闭环进度环，段头带完成徽章，数字可点直达缺项。
- **P5 不惩罚中断**：随时可补录（日历选日期）；顺延 / 跳过 / 失败 / 假期都是合法出口（`status=deferred`、`checkin.status=skip|failed`、`habit.paused_until`），不弹红色报错、不打断流。
- **P6 只落已有结构化列**：不新增列、不改表、不动 `docs/schema_v1.sql`。点选结果写成规范文案（§C′）。
- **P7 同构不同形**：同一交互语义，Windows 给键盘 + 托盘 + 多栏 + 悬停，Android 给拇指热区 + 手势 + 小组件 + 通知内操作。语义与数据契约必须一致（G6 判据）。
- **P8 一键可撤销，绝不弹确认框**：完成 / 顺延 / 取消 / 删除一律 toast + Undo（复用批次 G 已有的 toast 基建与 `tools/verify/toast_probe_check.py` 探针）。

## 3. §A′ 信息架构

页面清单固定 6 个：**今日**（默认落地页）· **待办池** · **习惯** · **项目** · **日历** · **设置**。

| 端 | 主导航 | 快捷入口 |
|---|---|---|
| Windows | 左侧固定导航栏（图标 + 文字，可折叠为纯图标条，折叠态记忆在 settings）；≥1280px 今日页双栏 | 托盘右键：打开今日 / 新建待办 / 快速打卡（列未打卡习惯）/ 退出；`Ctrl+N` `Ctrl+1..6` `Ctrl+D` |
| Android | 底部 5 Tab：今日 · 待办 · 习惯 · 项目 · 日历（设置在今日页右上齿轮）；Tab 长按 = 该对象的「今日视角」 | 桌面小组件一键打卡；通知内 Done / Skip / Snooze 不打开 App |

日期定位条统一置于顶部（今日页、日历页、待办池、习惯、项目）：

```
‹ 昨天    2026-11-07 周五    明天 ›      [补录模式]  [模式: 完整/极简]
```

- `今天` 按钮常驻（非今天时才高亮可点）。
- 选中日期由 `selectedDateProvider` 承载（**现状是 `todayProvider` 固定取今天，B1 需改为 selectedDate 驱动**）。
- 非今天 ⇒ 右侧显示 `补录模式`（过去）或 `预排`（未来）徽标。
- **未来日期只可预排 `plan_item`，不可打卡/回填**（§H-1）。

## 4. §B 今日页：三段闭环时间轴

一条可滚动时间轴，三段按当前时刻自动重排优先级，**永不折叠隐藏**。

### 4.1 顶部闭环环（LoopProgressRing）

```
计划 6/8   ·   回填 4/6   ·   复盘 ✍️   ·   心态 ✍️
```

- 四个数字/图标全部是按钮：点击滚到对应段并高亮该段缺项（缺项容器加 2px 强调描边 + 一次性提示）。
- 口径见 §G-1，唯一口径，不得在别处另算。
- **provider 口径（集中声明；与前文「选中日期由 `selectedDateProvider` 承载（现状是 `todayProvider` 固定取今天，B1 需改为 selectedDate 驱动）」一句、以及 §13.3 需改代码点、§14 B1 交付项同一口径）**：`selectedDateProvider`（选中日期，初值取今天）与 `vocabProvider`（词库）都是**待新增代码**，现状里不存在。实施时把今天日期从 `todayProvider` 迁到 `selectedDateProvider`，今日页 / 日历 / 成果回填 / 打卡 / 增量的日期写入一律只读 `selectedDateProvider`。本文不假设二者已存在，也不把迁移算作现状能力。

### 4.2 段① 晨 · 定计划

主路径（零打字）：

1. **从待办池捞** —— 弹层多选列表，默认按 `todo.due_date` 升序，`已到期 → 今天 → 无期限` 分组；点选即建 `plan_item(date, source_type='todo', source_todo_id, title=快照)`。多选后底部一条 `加入 今日 3 条`。
2. **今日该做的习惯** —— 按 `habit.schedule_type` 判定当天应做（daily / weekly_n / weekdays），一键全部选入（建 `is_habit_ref=1` 行）。
3. **从项目** —— 选项目 → 选里程碑（`project_milestone`）→ 自动带出该项目最近一笔增量的 `next_step` 作为标题建议（可改）。

兜底路径：`+ 手写一条`（保留现有底部输入框，降级为兜底入口，不再是主路径）。

新条目落「收件箱」子段，一行只展开三排芯片：**优先级（象限 4 格 / ABC 3 枚，随 settings.priority_mode 只显示一套）· 时长档位 · 领域**。三段都可选但不必填 ⇒ 零必填校验即可成立。

段尾汇总：`今日共 8 条 · 预估 4h15m`。当 `sum(est_minutes)` 超过设置阈值（默认 480 分钟）⇒ 温和提示「预估超出可用时间，考虑顺延 2 条」，并给「一键顺延最低优先级的 N 条」。**不阻止保存**。

### 4.3 段② 午 · 执行与打卡

条目行主体（从左到右）：勾选完成 · `title` · 优先级标签 · 来源徽标（待办/习惯/项目图标）· 结论芯片 · 实际时长芯片。

- **习惯打卡吸底卡带**（HabitCheckinStrip）：今天所有未打卡习惯横滑摆在这里，一点即打。位置固定在视口底部（Windows 为右下吸底卡，不遮挡列表）。这是全产品最高频动作，不允许需要向下翻才找到。
- **项目增量入口**在本段：`记一笔增量` 打开三段式增量器（进展 / 阻碍 / 下一步）：
  - `progress` 可点选今日相关条目自动带（写 `project_increment.plan_item_id`）；
  - `next_step` **默认预填上一笔增量的 `next_step`，点一下即接受** —— 对开发计划 R7「不闭环让用户不知该填什么」的直接回答；
  - 只追加不改历史（符合校验清单第 5 条「不强制每日闭环、自动聚合时间线」）；
  - 连续 3 天无增量的温和停滞提示直接附 `点一下补一笔` 按钮。

### 4.4 段③ 晚 · 复盘与心态

- 段头自动带出**当日事实**（§G-2）：未完成 3 条 · 结论分布 top2 · 习惯漏打 1 个 · 项目 N 天无增量。点这些事实即成为复盘内容，用户不必回忆或打字。
- `learning / good / improve / controllable / uncontrollable / next_action` 六段各 = 短语芯片（§C″）+ 可展开文本；`controllable` 项右侧带 `转待办` 一键；`next_action` 支持从今日未完成条目点选。
- `mood_note` = 5 枚状态短语芯片 + 文本兜底。
- **心态八维**（认真 / 快 / 坚守承诺 / 保证完成任务 / 乐观 / 自信 / 爱与奉献 / 决不找借口）：Windows 点 0–10 数字格，Android 横滑档位；写入 `day_log.mood_1..8`（`NULL` = 未打分）。一键 `今天没打分` ⇒ `mood_failed=1`，这是**合法状态**，闭环环按「已处理」显示，不算缺失。
- 「现在收工」按钮：把 18:00 之后的晚间段置顶并收起吸底卡带（一次性动作，不改变数据）。

### 4.5 极简模式（`day_log.mode='minimal'`）

三段压成：晨「捞 3 条最重要的」· 午「打勾 + 吸底卡带」· 晚「一句话 + 心态」。
切换入口在闭环环右侧（现有 `SegmentedButton` 移位复用）。**极简模式仍要求闭环**（计划/回填/心态各有最小动作），只是减少字段，不是取消段落。

## 5. §C 点选化控件清单（逐字段：控件 → 写入列 → 打字兜底）

### 5.1 `plan_item`

| 字段 | 控件与默认交互 | 打字兜底 |
|---|---|---|
| `title` | 不直接输入；从待办/习惯/项目选入自动带标题快照 | 仅 `+ 手写一条` |
| `date` | 顶部日期条 / `DatePickerSheet`（默认 selectedDate） | 无 |
| `source_type` / `source_id` / `source_todo_id` | 由入口决定，用户不感知 | 手写条目 = `manual` |
| `quadrant` | 4 格芯片 Q1 重要紧急 / Q2 重要不紧急 / Q3 紧急不重要 / Q4 既不紧急不重要；点标签弹浮层，再点已选项取消 | 无 |
| `priority_abc` | 3 枚芯片 A/B/C；与象限**两套都存、同一时刻只显示一套**（`settings.priority_mode`） | 无 |
| `domain` | 6 枚芯片：事业 / 财富 / 家庭 / 学习 / 人际 / 健康 | 无 |
| `est_minutes` | 档位芯片 5/10/15/25/45/60/90/120 | `自定义…` → 数字 |
| `planned_start` / `planned_end` | 半小时间格点选（06:00–24:00）+ `整块 1h / 2h` 快捷 | 无 |
| `status` | 勾选 = `done`；结论芯片含 `顺延到明天` = `deferred`、`取消` = `cancelled`；默认 `pending` | 无 |
| `done_at` | 自动写入 | 补录时在日历详情改 |
| `result_note` | **三段合成器**（§C′）：结论 → 原因 → 下一步 | 仅 `[下一步]` 自由位 |
| `is_habit_ref` | 来源为习惯时自动置 1 | `转为普通条目`（promote）；反向操作有意不做 |

### 5.2 `habit` / `habit_checkin`

- **打卡是一个大按钮，不是表单**：一点 ⇒ `habit_checkin(habit_id, date, status='done')`，再点取消（Undo）。
- `type='count'`：`±` 步进器 + 目标值直点（目标 8 杯 ⇒ 芯片「8」一次到位）；`value` 写实际值；常用档位 `+1 / +3 / 目标`。
- `type='avoid'`：两态按钮 `没破戒 ✓`（done）/ `破戒 ✗`（failed）。
- `type='checklist'`：`checklist_json` 渲染为勾选清单，全勾 = done。
- `type='normal'`：单按钮。
- `skip` / `failed` 均带原因芯片（出差 / 生病 / 假期 / 临时有事 / 其他）。
- `schedule_type` 未到期 ⇒ 该习惯**整条不出现**在吸底卡带与选入清单（不显示灰色不可点，避免噪音）。
- `paused_until` 非空 ⇒ 显示「假期模式至 X 日」，`暂停全部习惯` 一键（用 DatePickerSheet 选恢复日期）。
- 全程**不调出系统数字键盘**（count 用步进器，value 由步进器累加得到）。
- `habit_score`（score / streak / longest_streak）本地派生，UI 只展示，**绝不写入、绝不同步**。

### 5.3 `todo`

- 新建待办是**唯一必须打字的对象**（一条名字）。输入框下方同一弹层里立刻给四排芯片：
  - 到期：`今天 / 明天 / 本周内 / 选日期… / 无期限`；
  - 估时：档位芯片（同上）；
  - 领域：6 枚；
  - 归属项目：从项目列表点选（可空）。
- 状态：滑动 = `done`；长按/右键菜单 = `cancelled / archived`；`open` 为默认。
- 主操作按钮 = `加入今日`（不复制状态，符合 schema 注释「添加到今日计划 = 建 plan_item 行」）。
- 待办本体**不挂提醒**；进当日计划后才可开提醒（schema 约定）。

### 5.4 `day_log`

| 字段 | 控件 |
|---|---|
| `mode` | `SegmentedButton`（复用现状） |
| `learning` / `good` / `improve` / `controllable` / `uncontrollable` / `next_action` / `mood_note` | 短语芯片（可多选）+ 展开文本；写法见 §C′ 复盘字段格式 |
| `mood_1..8` | Windows 0–10 数字格点选 / Android 横滑档位 |
| `mood_failed` | 一键 `今天没打分` |

### 5.5 `project` / `project_milestone` / `project_increment`

- 项目名打字一次；`domain` / `status`（active/paused/done/cancelled）芯片；`start_date` / `end_date` 走 DatePickerSheet。
- 里程碑：文本一条 + `target_date`（日历）+ `achieved_at` 一键「达成」；无依赖关系、可排序。
- 增量：三段各带短语芯片库 + 文本兜底；`progress` 可点选今日条目（写 `plan_item_id`）；`next_step` 预填上一笔。

### 5.6 `reminder`

- `remind_at` = 日期（DatePickerSheet）+ 时间格 + 常用时刻芯片 `08:00 / 12:30 / 18:00 / 21:00`。
- `repeat_rule` = 4 枚芯片（不重复 / 每天 / 每周 / 每月），`yearly` 藏进 `更多`；`repeat_detail` 用 weekdays 芯片或日期格点选。
- 挂载入口**只在** `plan_item` / `todo` / `habit` / `project` 的详情里；一个实体可挂 N 条（schema 支持）。
- **不做提醒中心页**（MVP 仅固定时间提醒）。

## 6. §C′ 规范文案写入格式（不动 schema 的关键约定）

### 6.1 `plan_item.result_note`

```
[结论]延后完成 | [原因]预估不足 | [下一步]周四上午做完剩余两页
```

文法：

```
result_note := segment ( " | " segment )*
segment     := "[" label "]" text
label       := "结论" | "原因" | "下一步"      # 顺序固定，缺段省略、顺序不变
text        := 1..40 字符（字符按 Unicode 码点计），禁止包含 "|" "[" "]"
```

- 三段全空 ⇒ `result_note` 为 `NULL`（即「未回填」，参与 §G-1 回填率分母）。
- 只读态按 ` | ` 与 `[标签]` **反解回已选芯片状态**；反解失败（用户在外部编辑、或历史自由文本）⇒ 整段作为一段纯文本只读显示，并提供 `重新结构化` 按钮（点击清空原文重新走芯片，可 Undo 恢复）。
- UI 是「三行芯片，选完即成一句话」；只有 `展开` 箭头才出文本框，且自由文本只允许落在 `[下一步]`。
- **已知代价（用户已确认接受）**：文案被外部编辑后退化为自由文本，「结论分布」统计是尽力聚合而非硬保证。若将来需要强统计，明路是 schema v2 加 `plan_item.outcome_code` / `blocker_code` 枚举列 —— **本设计明确不做**，登记在 §I.3。

### 6.2 复盘字段（`day_log` 六段 + `mood_note`）

```
review_field := token ( " | " token )*
token        := 1..20 字符，禁止包含 "|"
```

- 多选短语用 ` | ` 连接；自由文本作为一个普通 token 追加在末尾（不带 `[标签]`）。
- `controllable` 转待办 ⇒ 只新建 `todo` 行，**不改** `day_log` 内容（保留可控项归因）。
- 反解失败同 6.1 处理（只读纯文本 + `重新结构化`）。

### 6.3 增量三段（`project_increment.progress / blockers / next_step`）

各段独立遵循 6.2 的 `review_field` 文法（短语 + 可选自由文本）。不跨段合成，保持导出可读性。

## 7. §C″ 短语芯片词库（内容资产，起步全量）

每条 = 稳定 `key`（英文 snake_case，仅用于本地统计与自定义映射）+ 中文 `label`（写库内容）。写库只写 `label`。

**结论 outcome（7）**：`on_time` 按时完成 · `late` 延后完成 · `early` 提前完成 · `partial` 部分完成 · `blocked` 受阻 · `defer` 顺延到明天 · `cancel` 取消

**原因 reason（8）**：`underestimate` 预估不足 · `interrupted` 被打断 · `external_dep` 依赖外部 · `priority_changed` 优先级变了 · `low_energy` 状态不好 · `time_short` 时间不够 · `unclear_info` 信息不清 · `other` 其他

**做得好 good（6）**：`on_plan` 按计划推进 · `proactive` 主动沟通 · `deep_work` 一次做透 · `learned` 学会了新东西 · `helped` 帮到别人 · `resisted` 顶住干扰

**待改进 improve（6）**：`procrastinate` 拖延 · `multitask` 多任务切换 · `no_boundary` 没设边界 · `optimistic_est` 估时太乐观 · `missing_sync` 缺前置沟通 · `late_review` 复盘不及时

**学到了 learning（5）**：`new_method` 新方法 · `pitfall` 踩坑经验 · `feedback` 他人反馈 · `reading` 资料启发 · `data` 数据结论

**可控 controllable（5）**：`start_earlier` 提前开始 · `break_down` 拆小一点 · `ask_help` 找人帮忙 · `block_time` 挡住时间 · `prep_first` 先备好前置

**不可控 uncontrollable（4）**：`other_people` 别人变了 · `sudden_event` 突发事件 · `external_result` 结果不由我 · `weather_env` 环境限制

**下一步 next_action（6）**：`continue_tomorrow` 明天继续 · `make_todo` 转成待办 · `delegate` 交出去 · `shrink` 缩小范围 · `review_later` 定日复盘 · `stop_it` 就此停止

**习惯跳过 skip_reason（4）**：`trip` 出差 · `sick` 生病 · `holiday` 假期 · `busy` 临时有事

**心态状态 mood_note（5）**：`steady` 平稳 · `rushed` 赶 · `focused` 专注 · `scattered` 散 · `grateful` 有支撑感

**档位类**：估时 `5/10/15/25/45/60/90/120` 分钟；时间格 `06:00–24:00` 半小时；常用提醒时刻 `08:00 / 12:30 / 18:00 / 21:00`；日期快捷 `今天 / 昨天 / 前天 / 明天 / 本周内 / 无期限`。

### 7.1 词库必须可自定义

**设置 → 词库**：按类别增删改短语、调整顺序、按领域分组；空态不允许（至少保留一条 `其他`）。
存储：`settings` 表一个 key（本机配置，`theme / priority_mode / week_start / sound` 已在此），**不参与同步**（设备本地词库差异不应污染对端）。若将来需要跨设备同步词库，属 schema v2 + 冲突策略范畴，本设计不做。

理由：词库不符合用户说法 ⇒ 用户回到打字 ⇒ 点选化整体失效。

## 8. §D 日历与日期选择

### 8.1 日历总览页 `/calendar`（双端同一 widget）

- 月网格 7×5/6，`week_start` 取 `settings`（1 = 周一，或周日）。
- 每格三层信息：
  1. **完成度底色**：done/total 渐变（全完成实心、部分完成渐变、空白无底）；
  2. **打卡热力点**：习惯 done/总数，用点数或迷你分段环；
  3. **心态迷你条**：`mood_1..8` 非 NULL 的均值；全 NULL 且 `mood_failed=1` ⇒ 灰点；全 NULL 未处理 ⇒ 空心点。
- 状态徽标（不只靠颜色，同带形状以满足无障碍）：`✓` 全完成 · `●` 有未完成 · `○` 完全空白 · `▸` 未来日期带排期。
- **计划与到期分色**：格子底部条 = 当天 `plan_item`（计划）；小旗 = `todo.due_date` 到期。两者绝不混用同一图形。
- 点某天 ⇒ Android 底部 Sheet / Windows 右侧详情栏：该日闭环摘要（计划 x/y · 回填 m/x · 复盘 · 心态）+ `打开这一天`（今日页切到该 date，过去日进入补录模式）+ `未完成 N 条` 直达列表。
- 导航：年/月切换、`今天` 按钮；Windows `←↑→↓` 移动、`Enter` 打开、`PgUp/PgDn` 翻月；Android 左右滑翻月、下拉回今天。
- 三视图：**月** · **热力年视图**（GitHub 风格 53 周网格，对应开发计划 P2-7）· **清单**（按月分组列出有记录的天）。

### 8.2 `DatePickerSheet`（全站唯一日期组件）

- 上半：快捷芯片行 `今天 / 昨天 / 前天 / 明天 / 本周内 / 无期限`（`无期限` 仅用于 `todo.due_date`）。
- 下半：月历（连续翻月、今天描边、周末标红、已选填充）。
- Windows：居中弹层；方向键 + `Enter` 可达；`Esc` 关闭；`PgUp/PgDn` 翻月。
- Android：底部 Sheet；滚动翻月；`今天` 吸底大按钮。
- **共用范围（G6 硬判据）**：`plan_item.date`、`todo.due_date`、`project_milestone.target_date`、`project.start_date/end_date`、`habit.paused_until`、`habit.start_date`、`reminder.remind_at` 的日期部分。任何页面不得自造日期选择控件。

### 8.3 补录语义

- `date` 为过去日 ⇒ 徽标 `补录模式`；`done_at`、`created_at`、`updated_at` 保持真实操作时刻，**不伪造历史**。
- 补录不改 `day_log.date` 唯一性语义（一天一行）。

### 9.1 窗口与壳

- 默认 1200×800，最小 960×640；关闭 = 收进托盘（沿用 `desktop_shell.dart`，批次 G 已定性：Win11 通知区折叠属可见性问题、非缺陷）。

### 9.2 设置 → 系统：开机自启开关（本轮新增的真实缺口）

- 一个 `AutostartToggle`，读写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`（与 `installer.nsi:52` `RUN_KEY` 完全一致的键与值名）。

| 键 | 动作 |
|---|---|
| `Ctrl+N` | 从待办池捞（打开选入弹层） |
| `Ctrl+Shift+N` | 手写新待办 |

## 11. §G 计划 → 记录 → 评价 联动规则

1. **闭环环唯一口径**
   - 计划 `x/y`：`y = COUNT(plan_item WHERE date=sel AND status!='cancelled')`，`x = COUNT(status='done')`；
   - 回填 `m/x`：`m = COUNT(done 且 result_note IS NOT NULL)` ÷ `x`（`x=0` ⇒ 显示 `—`，不算 100%）；
   - 复盘：`day_log.good` 或 `improve` 或 `learning` 非空 ⇒ ✓；
   - 心态：`mood_1..8` 至少一个非 NULL **或** `mood_failed=1` ⇒ ✓（两者皆无 ⇒ ✍️）。
2. **事实自动带出**（复盘段头，纯 SQL、零打字）：未完成条目列表 · 结论分布 top2（解析 `result_note` 的 `[结论]`，解析失败的条目计入「其他」）· 习惯漏打（应做 − 实做）· 项目无增量天数（`julianday` 差按 `date` 算）。
3. **正向链**：`day_log.controllable` 一键转 `todo` → 次日晨段一键选入 `plan_item`（保留 `source_todo_id` 与标题快照，待办改名不影响历史）。
4. **未完成不自动消失**：次日顶部「昨日遗留 N 条」卡片，一键 顺延 / 取消 / 留下。顺延 = **新 `plan_item` 行（date=今天）+ 老行 `status='deferred'`**，绝不覆写历史。
5. **习惯三处现身**：晨段选入清单（`schedule_type` 判定）· 午段吸底卡带 · 晚段「坚持/漏打」汇入复盘事实。
6. **项目与计划互带**：条目详情显示该项目最近 3 笔增量；增量「进展」点选今日条目写 `increment.plan_item_id`；「下一步」预填上一笔。
7. **周报（P6）只消费上述聚合**，不新增任何录入负担、不新增字段。
8. **评价回看**：晚段心态八维与结论分布同屏呈现；趋势在日历热力年视图上看。

## 12. §H 边界、异常与性能

1. **未来只读预排**：允许给未来日期建 `plan_item`（徽标 `预排`）；**打卡、回填、复盘、心态只允许今天与过去**。
2. **跨零点**：`date` 是本地日历日；凌晨 00:00–05:00 提交 ⇒ 默认落「昨天」并明确提示，可一键改为今天。
3. **时区**：时刻一律 INTEGER Unix ms UTC（schema 约定不变）；日期一律本地 `TEXT 'YYYY-MM-DD'`。UI 不得把两者混用。
4. **首次使用**：3 步引导（建 3 条待办 → 选 1 个习惯 → 定今日），每步可跳过，全程点选；不强制注册。
5. **空态即入口**：每个空态文案直接给主操作按钮（「还没有今日计划，从待办池捞一条」+ 按钮），不出现纯装饰性空态。
6. **性能红线**：月视图一次查 42 天、热力年视图一次聚合 371 天，必须走 `idx_plan_item_date_status` / `idx_habit_checkin_date` / `day_log_date_unique`；**禁止按格子 N+1 查询**。
7. **同步安全**：所有点选写入必须走现有 `rev` 递增与 oplog 路径；UI 不做本地乐观合并。P5 多设备接入后，冲突由 lamport 定序，本设计的交互不新增冲突面（`UNIQUE(habit_id,date)`、`day_log.date UNIQUE` 已是幂等锚点）。
8. **可撤销**：完成 / 顺延 / 取消 / 删除 / 重新结构化 五类操作必须提供 Undo（toast 内，8 秒），不弹确认框。
9. **失败路径不静默**：写库失败 ⇒ toast 报错 + 保留已选芯片状态可重试；绝不清空用户输入。

**验收方式（用户拍板）**：每批都以构建产物真机为准，`flutter dev` 不可用于界面验收；需要装机实测的流程**直接打包 exe**（`tools/build/make_installer.ps1`），不等用户要求。

新增真机验收场景（补开发计划 12 条之上）：

1. **零打字闭环**：从待办捞 3 条 → 打勾 2 条 → 结论芯片填 `result_note` → 打卡 1 个习惯 → 复盘各选 1 短语 → 心态数字格打分，全程不碰键盘，检查落库文案符合 §6.1/§6.2 文法。
2. **反解健壮性**：手工把一条 `result_note` 改成自由文本，UI 必须降级为只读纯文本 + `重新结构化`，不崩溃、不丢数据。
3. **补录**：日历点 5 天前的空白天 → 建 2 条计划并打卡 → 徽标显示 `补录模式`，`done_at` 保持真实时刻。
4. **预排不可打卡**：给明天建 `plan_item`，明天之前的界面上不允许出现打卡/回填入口。
5. **DPI/字号**：144dpi（×1.5）+ 系统字号 200%，芯片换行不溢出、吸底卡带不遮挡、闭环环不截断。
6. **键盘全通路**：仅用 Tab/Space/Enter/方向键完成一次晨段闭环（不依赖鼠标）。
7. **开机自启开关**：设置里关掉再打开，`HKCU\...\Run` 值随之消失/出现；重启系统后应用自启/不自启与开关一致。
8. **词库自定义生效**：删掉一个短语 ⇒ 全站不再出现；新增一个 ⇒ 立即可点选并正确写入。
9. **Undo**：误点顺延后 8 秒内 Undo，数据回到原状（老行仍是 `pending`、无新行）。
10. （B5）**通知内操作**：不打开 App 完成 Done/Skip；（B5）**小组件打卡**：桌面点一下即写 `habit_checkin`。
11. （B5）**提醒可靠性**：开启电池优化的设备上，提醒不来时设置页引导能把它救回来。

## 16. §L 风险与开放问题

1. **词库内容是本设计最大的软资产**（§C″）。起步词库来自《高绩效人士的五项管理》与 MVP 词表，但**未经用户实际使用验证**。B1 上线后需要用真实一周记录校准；`VocabEditor` 必须在 B2 到位，否则失效风险高。
2. **规范文案的统计可靠性**（§6.1）：结论分布是尽力聚合。若后续对「硬统计」有需求，走 schema v2，需重跑 G1–G3 并设计新列的同步冲突策略。
3. **`selectedDateProvider` 改造有回归面**：现有 6 个测试文件与 47 个用例覆盖 `todayProvider`，B1 会改动数据入口，需先补一版针对 date 参数的失败用例（TDD）。
4. **B5 前 G6（双端一致性）无法验证**：Android 工程不存在，双端判据只能到 B5 才落地。B1–B4 期间一致性靠「组件下沉 + 单一口径 provider」保证。
5. **Android 提醒可靠性**（§10.5）是厂商差异大、最容易假成功的区域，必须真机验证，不能只看代码路径。
6. **窗口宽度阈值（1280/1920）与密度三档**需要真机观感确认，纸面数值可能偏理想。
7. 交接卡遗留的非交互项（真机中文向导观感、更新安装回填旧路径、`userdata` 非管理员可写性、§10 残留垃圾约 126MB 未删）**不在本 spec 范围**，仍按批次 G 的待办单独推进。
