## 1. 为什么用这两本书当骨架

本项目是**个人时间管理系统**，不是任务清单工具。两本书恰好覆盖本系统的两个失败模式：

| 失败模式 | 现象 | 对应要点 | 本项目病灶 |
|---|---|---|---|
| 记了不做 | 待办池越堆越多，方格时间轴常年半空 | 德鲁克·要事优先 / 柯维·要事第一 | 待办池 → 方格之间只有一个「捞」动作，没有容量判断 |
| 做了不闭环 | 每天都在排期，但说不出推进了什么 | 德鲁克·聚焦贡献 / 柯维·以终为始 | 复盘 6 个字段全是自由文本，不产生次日动作 |

一句话：**本系统已经有「记录」和「排期」，缺的是「判断」和「回灌」。** 下面 14 条建议全部围绕这两件事，
不新增任何 schema、不新增任何依赖（沿用 Task 40 的硬约束口径）。

## 3. 逐条建议

### M1 · 待办池 → 今日排期的「容量闸门」（P0）

**理论锚点**：德鲁克《卓有成效的管理者》—— 掌握时间的第一步是先知道时间实际去了哪里，而不是先排新的。

**现状（实测）**
- `pages\todo_pool_page.dart:523` 有 `ValueKey('todo-pull-${todo.id}')`，这枚按钮是待办池进今日的**唯一**路径。
- 同文件 `:415` 的 `_PoolHead` 只是表头，不显示任何容量信息。
- `widgets\timeline\day_grid.dart` 里 `kSlotMinutes` 是 15 分钟一档，但页面没有任何地方汇总「今日已排多少分钟」。
- 参照量其实是现成的：`pages\settings_page.dart:303` 与 `:317` 已经有「计划窗口起止小时」的下拉（`settings-plan-start` / `settings-plan-end`）。

**动作**
1. 在 `_PoolHead`（`todo_pool_page.dart:415`）右侧加一段只读文本：`今日已排 {X} 分钟 / 窗口 {Y} 分钟`。
2. `X` = 当日 `plan_item` 的 `est_minutes` 之和（`est_minutes` 字段见 `docs\schema_v1.sql:133`，且已有 `plan_item_est_minutes_check` 保证 `>= 0`）。
3. `Y` = `(plan_end_hour - plan_start_hour) * 60`，取自既有 `settings` 表，不新增字段。
4. 当 `X > Y` 时，`todo-pull-*` 按钮降级为次要样式（`AppTokens.ink2` 字 + `hair` 边），并在按钮 tooltip 里给一句原因，而不是禁用 —— 德鲁克的口径是让用户看见超载，不是替用户拒绝。

**验收判据**
- 新增 widget test：给定 3 条 `est_minutes` 分别为 30/45/25 的今日条目，`_PoolHead` 渲染出 `已排 100 分钟`。
- 100% 与 150% 文字缩放两档下 `_PoolHead` 不产生 `RenderFlex overflowed`。

**成本**：约 60 行 + 1 个 test。无 schema 变更（`est_minutes` 已在 `plan_item`）。

### M2 · 复盘「下一步可控动作」一键落成次日计划（P0）

**理论锚点**：柯维《高效能人士的七个习惯》—— 以终为始：任何一次结束都应当产出下一次的开始。

**现状（实测）**
- `widgets\review_section.dart:34-41` 的 `_fields` 目前是 **6 个字段**：学到了什么 / 做得好 / 待改进 / 可控的事 / 不可控的事 / 下一步可控动作。
- `:72` `_draft`、`:86` `_persistTo` 说明这 6 个字段全部写了 `day_log` 的自由文本列。
- 「下一步可控动作」是唯一带有**未来指向**的字段，但它落库后**没有任何消费方** —— 用户第二天要自己再抄一遍进方格。

**动作**
1. `ReviewSection` 保存成功后，判断「下一步可控动作」是否非空。
2. 若非空，且次日 `plan_item` 里不存在 `title` 完全相等的条目，则显示一枚 `ValueKey('review-to-tomorrow')` 的次按钮，文案 `→ 明天第一条`。
3. 点击调既有写入口 `planItem.create(date: 次日, title: 该字段文本)`，**不写 quadrant、不写 planned_start**（落进未排期带，让用户自己排 —— 排期是判断，不该由复用代劳）。
4. 幂等：以「次日 + title 精确相等」查重，重复点击不再建行；查重命中时按钮文案换成 `已在明天`。

**验收判据**
- 新增 test：写一条「下一步可控动作」→ 点按钮 → `plan_item` 多一条次日记录；再点一次 → 仍是 1 条。
- 「下一步可控动作」为空时按钮不出现（不出现禁用态按钮，避免噪音）。

**成本**：约 40 行 + 1 个 test。复用 `PlanItemRepository.create`，无新依赖。

**现状（实测）**

### M4 · 四象限分布从「计数」升级为「判断」（P1）

**理论锚点**：柯维 —— 要事第一：Q2（重要不紧急）的占比决定长期产出。

**现状（实测）**：`widgets\timeline\todo_rail_panel.dart:286` 的 `PriorityDistributionPanel` 与 `:429` 的 `_QuadrantCell` 只显示四个象限的**数量**。四象限图标已在 Wave A 改为星/铃体系（`widgets\priority_marks.dart:45` `Icons.star`、`:53` `Icons.notifications`）。

**现状（实测）**：`widgets\timeline\unscheduled_strip.dart:22` 的 `UnscheduledStrip`、`:82` 的 `_chip` 按库返回顺序渲染，没有排序参数；`:67` 的 `_setQuadrant` 只处理分级。

### M6 · 循环任务：「跳过一次」与「暂停整条」分离（P1）

**理论锚点**：德鲁克 —— 有效决策：决策必须写明「这次不做，还是以后都不做」。

**现状（实测）**：`widgets\recurring_rail_panel.dart:347` 的 `_OccurrenceRow` 是单行渲染；`:151` 的 `_buildToday` 与 `:111` 的 `_SectionTitle(text: '今日')` 是当前结构。规则实体在 `packages\core_data\lib\src\recurring.dart`（361 行），occurrence 与 rule 在数据层是两件事。

**动作**
1. `_OccurrenceRow` 增加行级菜单，两项：
   - `跳过一次` → 只把该 occurrence 标记为跳过，**不改规则**；
   - `暂停整条` → 改规则状态，后续不再产生 occurrence。
2. 两项的确认文案必须不同，且「暂停整条」必须走 `widgets\confirm_dialog.dart`（Wave A 已落盘的公共确认组件）。
3. 菜单项顺序固定为「跳过一次」在前 —— 破坏性小的一律在前。

**验收判据**
- 断言「跳过一次」后规则实体字段零变化（只多一条 occurrence 状态）。
- 断言「暂停整条」后当日 occurrence 数量不再增长。

**成本**：约 70 行 + 2 个 test。

### M8 · 设置页「重置」按影响面分级确认（P1）

**理论锚点**：德鲁克 —— 有效决策：先分类，再确认；把「改偏好」和「删数据」当成一回事是决策失败。

**现状（实测）**：`pages\settings_page.dart:401` 是 `settings-reset-button`；`:125` / `:130` 是 `settings-reset-cancel` / `settings-reset-confirm`，同一个确认流程。而设置页同时承载偏好（主题 `:194-210`、语言 `:231-239`、密度 `:345-361`、优先级体系 `:380-386`）与计划窗口（`:303` / `:317`）。

**动作**

### M9 · 关于页文字按钮键盘可达（P1）

**理论锚点**：柯维 —— 知彼解己：先按用户真实输入方式（键盘）验证你的界面，而不是只按你自己的方式（鼠标）。

**现状（实测）**：`pages\about_page.dart:259` 的 `_LinkButton` 内部是 `InkWell`（`:273`），外层是 `Container`（`:276`）。`InkWell` 本身可被语义识别，但没有 `Focus` / `FocusableActionDetector`，Tab 遍历到不了；且 `:282` 的边框是静态色，没有 focus 视觉态。关于页共有 8 枚这类按钮（`:124` / `:131` / `:167` / `:172` / `:195` / `:210` / `:231` 等）。

**动作**
1. 把 `_LinkButton` 换成 `TextButton` + `OutlinedButton` 风格，或保留 `InkWell` 但外套 `FocusableActionDetector`。
2. focus 态边框用 `AppTokens.ink`（`theme\app_tokens.dart:35`），hover 态维持 `hairStrong`（`:282` 现值），两者**必须可区分**。
3. 禁用态（`onTap == null`，`:272` 的 `enabled`）不进 Tab 序。

**验收判据**
- 纯键盘 Tab 能从页面顶部走完全部可用按钮，禁用按钮被跳过。
- 断言 focus 态边框色 ≠ hover 态边框色。

**成本**：约 30 行 + 1 个 test。注意：本轮 Task 40 明令**不改** `about_page.dart`，此条属下一轮。
