## 2. 纸质实例的结构与缺陷（设计输入）

> 6 张实例图原始路径（顺序 = 用户编号）见附录 A。图 3/4/5 为手填件，OCR 有噪声，本规划**只取表结构与列语义**，不引用具体文字内容。

### 2.1 图 1 / 图 2 人生蓝图

结构：**6 类别（事业 / 财富 / 家庭生活 / 学习成长 / 人际关系 / 健康休闲）× 5 时间跨度（终极·60 岁后 / 远期·10 年 / 中期·5 年 / 短期·3 年 / 近期·1 年）**，每格三层：**目标（一句话）→ 关键词（手段）→ 做法（行动）**。

缺陷（软件要修正的）：
1. 一格三层写在同一格里，「做法」无法被追踪、无法与周计划相连 ⇒ 拆成三层不同实体（§5.4）。
2. 图 2 存在**整行留空**（如某类别只填了「终极」）⇒ 空格是常态，任何「必填」「按顺序填」的校验都会挡正常路径（参照项目页规划「别加会挡正常路径的 CHECK」教训）。
3. 「近期（1 年）」列与图 3/图4 年度目标表**内容重复** ⇒ D-62-f 单一真源。
4. 无「服务于」链：年/月/周与蓝图格之间纸面没有引用关系，导致日常执行与愿景脱节 ⇒ 本规划的核心补强（H2 以终为始）。

### 2.2 图 3 / 图 4 年度目标

- 表一列：**类别 / 序号 / 目标内容 / 方法和措施 / 起止时间 / 完成打 √**。
- 表二把「方法和措施」横向展开成 **1–12 月**，每月三列：**月目标 / 具体做法 / 得分**，另加**修正方案**。
- 页脚年度复盘：**完成 X 项 / 总得分**。

缺陷：
1. 「得分」无口径 —— 是自评还是达成度？两者混用一列（§6.2 D-62-e 拆开）。
2. 表二的 12 个「月目标」与图 5 的「本月目标」是**同一数据抄两遍** ⇒ 年视图的月份列应下钻到月目标，不重复录入。
3. 「起止时间」自由书写，无法参与排期 ⇒ 落 `period_start / period_end`。
4. 「完成打 √」是二值，丢信息 ⇒ 保留 done，同时用 `self_score` 表达程度。

### 2.3 图 5 本月目标

- 上半：**上月目标**逐条 → 实际完成 ✓/✗ / 未完成原因分析 / 改进措施。
- 下半：类别（财务 / 客户 / 管理指标 / 学习成长）/ 序号 / 本月目标 / 方法和措施 / 完成打 √。

缺陷：
1. 上半区是**复盘**却混在目标表里 ⇒ 拆成「复盘区 + 目标区」两块，复盘区数据仍属同一条 goal 行（`self_score / review_note / improve_note`），避免第二实体。

缺陷（也是本模块最值得学的地方）：
1. 说明 ① 就是**对齐链**（周 ← 月），纸面只能靠自觉 ⇒ 软件把它做成界面默认动作（从本月目标一键带出候选，§6.4）。
2. 「优先顺序」是纯序号，不带「为什么重要」⇒ 复用已有 `Quadrant`（Q1–Q4）让排序有语义（H3）。
3. 「完成期限（周几）」= 周内 due date，纸面无法提醒 ⇒ 落 `due_date`，接现有提醒机制（注意 `reminder.target_type` 不含 goal，故提醒在 app 侧按 `period_start/due_date` 驱动，§6.5）。
4. 左栏「48 周总结」与右栏「本周工作目标」**互不引用**，回顾不闭环 ⇒ 合并成同一页的两块，回顾结论可回写为下周目标（§5.1）。
5. 「完成一项打 ✓」只给布尔 ⇒ 与 `plan_item.status` 对齐后，完成事实应来自**实际计划项**，不由用户重述（Drucker 反馈 +《原则》证据链，§6.2）。

### 2.5 跨表共性缺陷（软件层面的总账）

| 纸面问题 | 本规划的处置 |
|---|---|
| 同一内容在蓝图/年/月三处抄写 | 单一真源 + 投影视图（D-62-f） |
| 目标与日常执行无引用链 | `goal_link` 多态表 + 「服务于」链 + 未落位提醒（H2） |
| 「得分」口径混淆 | 自评入库、达成度派生（D-62-e） |

| 完成状态靠用户手打 ✓，易失真 | 完成事实源于 `plan_item` / `habit_checkin`，用户只补自评 |
| 无「时间去哪了」的校验 | 用已有时间记账派生「宣称领域 vs 实际投入」一致性看板（Drucker） |

### 3.1 为什么不能一次加 4 个导航项【实测 + 推断】

### 3.2 三条实现路线对比与裁决

| 路线 | 做法 | 判定 |
|---|---|---|
| **A. 零 schema 复用** | 目标 = `project`（domain 充当类别），年/月 = `project_milestone`，周记录 = `project_increment`，行动 = `todo`；关系靠 `note` 文本前缀 | **否**。① `project` 无 `parent_id`【实测 :298-320】⇒ 4 级链只能靠 note，脆弱；② 无法表达 6×5 horizon 矩阵与「目标/关键词/做法」三层；③ `project_increment` 是 `progress/blockers/next_step`，无 score 列，与「月度得分/修正方案」语义不符；④ 周目标行若落 `todo` 会污染待办池（待办池是未排期工作池，不是愿景层）；⑤ 会把 project 页的 `paused/归档` 语义混进目标语义，日后两页都改不动 |

## 4. Schema 规划（v3 增量）

### 4.1 `goal` 表（5 种 kind 共表）

```sql
CREATE TABLE goal (
  id               TEXT PRIMARY KEY,                 -- UUIDv7
  kind             TEXT NOT NULL,                    -- blueprint | brand | yearly | monthly | weekly
  title            TEXT NOT NULL,                    -- 目标一句话（Drucker：必须本人撰写）
  note             TEXT,                             -- 展开说明 / 愿景描述
  keywords         TEXT,                             -- 蓝图「关键词（手段）」层；其余 kind 可复用为标签串
  parent_id        TEXT,                             -- 自引用，NULL = 顶层；仿 reminder 不建 FK
  domain           TEXT,                             -- Task 59 六 key；NULL = 未分类
  horizon          INTEGER,                          -- 蓝图档位 1 终极/2 远期/3 中期/4 短期/5 近期；其余 NULL
  facet            TEXT,                             -- 品牌画像切面；其余 NULL
  period_start     INTEGER NOT NULL DEFAULT 0,       -- Unix ms UTC；非周期目标 = 建档时刻
  period_end       INTEGER,
  due_date         INTEGER,                          -- 周目标「完成期限（周几）」落具体日
  quadrant         INTEGER,                          -- 复用 Quadrant 1..4（enums.dart:19）
  priority_abc     TEXT,                             -- 复用 A/B/C（enums.dart:60）
  status           TEXT NOT NULL DEFAULT 'active',   -- draft | active | done | cancelled
  self_score       INTEGER,                          -- 自评 0..10，NULL = 未评（仿 day_log mood CHECK 风格）
  review_note      TEXT,                             -- 未完成原因 / 障碍
  improve_note     TEXT,                             -- 改进措施 / 克服对策
  archived_at      INTEGER,                          -- 取消线，仿 plan_item:158
  created_at       INTEGER NOT NULL,
  updated_at       INTEGER NOT NULL,
  deleted_at       INTEGER,                          -- 墓碑
  origin_device_id TEXT,
  rev              INTEGER NOT NULL DEFAULT 1,
  CHECK (kind IN ('blueprint','brand','yearly','monthly','weekly')),
  CHECK (status IN ('draft','active','done','cancelled')),
  CHECK (horizon IS NULL OR horizon BETWEEN 1 AND 5),
  CHECK (self_score IS NULL OR self_score BETWEEN 0 AND 10),
  CHECK (quadrant IS NULL OR quadrant BETWEEN 1 AND 4),
  CHECK (priority_abc IS NULL OR priority_abc IN ('A','B','C')),
  CHECK (period_end IS NULL OR period_end >= period_start),
  CHECK (status = 'done' OR archived_at IS NULL)     -- 只有完成的东西才能进历史，仿 project
);
```

**刻意不加的约束**（依据项目页规划教训「别加会挡正常路径的 CHECK」，以及图 2 整行留空的事实）：
- 不要求蓝图必须 5 档齐填、不要求每个 domain 都有目标、不给 `title` 设长度或格式校验、不要求 `parent_id` 必填（顶层愿景本来就没有上级）。

### 4.2 `goal_link` 表（多态关联，仿 `reminder:364-394`）

```sql
CREATE TABLE goal_link (
  id               TEXT PRIMARY KEY,
  goal_id          TEXT NOT NULL,                    -- 不建 FK，仿 reminder:364-366
  target_type      TEXT NOT NULL,                    -- todo | plan_item | project | increment | habit | goal
  target_id        TEXT NOT NULL,
  relation         TEXT NOT NULL DEFAULT 'serves',   -- serves | derives | tracks | references
  created_at       INTEGER NOT NULL,
  updated_at       INTEGER NOT NULL,
  deleted_at       INTEGER,
  origin_device_id TEXT,
  rev              INTEGER NOT NULL DEFAULT 1,
  CHECK (target_type IN ('todo','plan_item','project','increment','habit','goal')),
  CHECK (relation IN ('serves','derives','tracks','references')),
  CHECK (target_type != 'goal' OR target_id != goal_id),   -- 禁自环
  UNIQUE (goal_id, target_type, target_id)                  -- 墓碑场景：重新关联时复用该行并清 deleted_at
);
```

`relation` 语义（这四种覆盖纸表全部关系，且不必扩 `plan_item.source_type`）：

| relation | 含义 | 典型 |
|---|---|---|
| `serves` | 本目标服务于上层目标 | 周目标 → 月目标 → 年目标 → 蓝图格 |
| `derives` | 由上层派生出的草稿 | 滚动生成的下周目标 → 本周目标 |
| `tracks` | 本目标的完成证据挂在执行层实体上 | 年目标 → `plan_item`；身份目标 → `habit` |
| `references` | 弱引用，跨模块看料 | 品牌画像 → `project` |

不建 FK 的理由与代价（照 `reminder` 已有取舍）：删除执行层实体时不级联，**读时统一 `deleted_at IS NULL` join 过滤**；孤儿链接在 UI 显示为「已失效引用」而不是被静默清掉（项目页 §4.1 风险的处置方式）。

### 4.3 派生不入库清单（明确列死，防实现时偷懒物化）

| 指标 | 怎么算 | 为什么不入库 |
|---|---|---|
| 目标完成度 / 完成率 | `goal_link relation='tracks'` join `plan_item.status` 现算 | `schema_v1.sql:34-36`；新设备重算 |
| 周/月/年「完成 X 项」汇总 | 按 `period_start` 窗口聚合 `goal.status` | 同上 |
| 蓝图格「是否已落待办」 | 查 `goal_link target_type='todo'` | 同上 |
| 「未落位」链断裂标记 | 沿 `serves` 链向下遍历，叶子无子即断 | 同上 |
| 宣称领域 vs 实际投入一致性 | `day_log` + `plan_item` 时长 + `habit_checkin` 频次，按 domain 归一 | 同上；数据源已全在库内 |
| 自评 `self_score` | —— | **例外：这是用户主观数据，属于源数据而非派生，必须入库** |

不使用 JSON 逃逸口（`habit.checklist_json` 范式）：本模块结构可被上述两表 + 三个枚举列完整表达，塞 JSON 会让 `goal_link` 的多态优势和「链断裂」查询同时失效。

**视图**：

### 5.3 年度目标

**数据**：`kind='yearly'`，`period_start/end` = 年度窗口，`domain`、`keywords`（方法和措施）、`self_score`。

**视图**：
- 表一（图 3）：类别 / 序号 / 目标内容 / 方法和措施 / 起止时间 / 完成 ✓。
- 表二（图 4）：1–12 月的「月目标 / 具体做法 / 得分」**不重复录入** —— 单元格实时渲染该月 `goal_link serves` 的月目标与其 `self_score`。空格即「该月未展开」，点击就地新建月目标并自动挂链（消除图 3/图 4 与图 5 的三处抄写）。
- 年度复盘：完成 N 项（派生）/ 自评总分与均值（源自 `self_score`，明确标注为用户自评，不叫「达成率」）。
- 「80/20 视角」：按 `serves` 链聚合展示「哪 20% 的年度目标贡献了多数已完成动作」，用 `tracks` 计数排序（只呈现，不打分、不排名）。

### 5.4 人生蓝图（6×5 矩阵）

**数据**：`kind='blueprint'`，一行 = 一个格子 = 一条 `goal`（`domain` + `horizon`）；三层落位：**目标 → `title`（+ `note` 展开）／关键词 → `keywords`／做法 → 子 `todo`（经 `goal_link`，relation `serves`/`tracks`）**。

**视图**：
- 主视图 = 6 行（domain）× 5 列（horizon）矩阵，格子内显示 `title` 一行 + `keywords` 标签 + 做法条数；点击展开三层。
- 「近期（1 年）」列**渲染该年度 yearly 目标**（D-62-f），不新建 blueprint 行；若用户手动往这格写内容，保存时转为 yearly 目标并挂 `serves` —— 保证单一真源。
- **链断裂可视化**：沿 `serves` 链向下探，若某格没有任何下级（年/月/周）或任何 `tracks` 执行实体，格子角标显示「未落位」，可一键「拆成 3 条待办」（走 `TodoRepository.create`）—— H2 以终为始的落地。
- 空格合法：矩阵不校验、不强制、不给红字（图 2 现实事实）。
- **平衡轮视图（H7 不断更新）**：6 domain × 自评 `self_score` 的趋势雷达，数据来自各层目标自评 + `habit_checkin` 频次；纯派生、不落库。

**判据**：任一 blueprint 格可在 ≤2 次点击内到达其对应周目标；`horizon` 与 `period_start` 一致性由 UI 保证（不建跨表 CHECK）。

### 5.5 个人品牌画像（实例没有，本次新增）

**定位**：蓝图回答「我要成为谁」，品牌画像回答「别人凭什么这样认为我」。它是**目标体系的诊断层**（Rumelt：诊断 → 指导方针 → 连贯行动 ⇒ 品牌画像 → 蓝图 → 年/月/周），不是装饰页。

**数据**：`kind='brand'`，一行一个切面，用 `facet` 区分：

| facet | 字段落位 | 名著依据 |
|---|---|---|
| `statement` 定位语句 | `title` = 一句话（「我为__解决__， unlike __，我__」） | Trout & Ries《定位》：心智中一个词 |
| `word` 心智一词 | `keywords` 首个标签 | 同上 |
| `audience` 对象/他人视角 | `title` + `note`，**必填提示「用第三人称写」** | 七习惯 H5 知彼解己 / H4 双赢 |
| `promise` 承诺结果 | `title` | StoryBrand：成功承诺 |
| `cost` 规避的代价 | `title` | StoryBrand：避免失败 |
| `evidence` 可信证据 | `title` + `goal_link(target_type='project'/'habit')` | StoryBrand 证明环节 +《原则》可追溯 |
| `contrast` 对立面（我不做什么） | `title` + `keywords` | 《定位》差异化、刺猬三环交集 |
| `strength` 三环交叉 | `title`（热爱 × 擅长 × 经济引擎），`note` 三段 | Collins《从优秀到卓越》刺猬理念 |
| `errc` 剔除/减少/增加/创造 | `title` + `keywords` 四组 | 《蓝海战略》ERRC |
| `identity` 身份声明 | `title`「我是 ___ 的人」+ `goal_link(target_type='habit')` | Clear《原子习惯》身份驱动 |

**视图**：
- 一屏一卡 + 左侧切面导航（壳内状态，不 push 路由）；每个切面给**填写范例与反例**（l10n 文案，zh/en）。
- **「他人视角优先」顺序锁定**：打开品牌画像时默认落在 `audience` 而非 `statement` —— 强制先答「别人会怎么描述你」再写定位语句（H5 先理解再表达）。
- **一致性校验（派生，不阻断）**：把画像关键词与近 N 周 `plan_item` 标题 / `habit` 名做词面重合度提示，例如「画像强调『专业深度』，但近 8 周 0 条相关投入」—— 这是把 Drucker「知道时间花在哪儿」和《原则」证据链合到一处。
- **一键转目标**：`identity` / `promise` 均可生成 yearly 目标（草稿 + 确认，D-62-g），并挂 `serves` 到对应 blueprint 格；`identity` 可生成 `habit` 关联建议。

### 5.6 五页签的默认顺序与落地页

页签顺序 = **周 | 月 | 年 | 蓝图 | 画像**（按使用频次降序，画像最右）；`Ctrl+6` 进入时默认落在**周**页签（工作现场），上次所在页签记在 `appPreferencesProvider`（`providers.dart:371`）—— 与 Task 61 已确立的壳层偏好口径一致。

### 6.2 反向：待办 / 计划侧显示所属目标

- 待办池与今日右栏的每条待办、时间轴每个计划项，若有 `goal_link target_type IN ('todo','plan_item')` 记录，卡片显示目标 chip（复用 `domain_chips.dart` 的视觉语言，chip 内容 = 目标 `title` 截断）。
- 点击 chip = 在壳内展开该目标的最小上下文（所属链：周 ← 月 ← 年 ← 蓝图格），不跳转路由。
- **完成不回写目标状态**（避免假级联，项目页 §8 教训）：计划项 done 只让「完成度」派生值变化；目标 `status` 仍由用户判定。这条要在 UI 上说明，否则用户会以为勾完子任务目标就 done。

### 6.3 今日页右栏的「自动调用」

- 新增第 5 面板「本周目标」：`app.dart:384-416 todayRailPanels()` 追加 `ShellRailPanel`（`tool_rail.dart:11-29`），trailing id 依 `rail-add-goal` 惯例，复用 `_RailPanelChrome:178` / `RailAddButton:256`；面板实现仿右轨先例 `todo_rail_panel.dart` / `recurring_rail_panel.dart`。

  - (b) 并入 `LoopHintPanel`（`:904` 起）作第 5 行 —— 语义混淆（循环提示 vs 目标清单），不推荐；
  - (c) 仅 `>=1920` 显示 —— 多数用户看不到，违背「自动调用」诉求，不推荐。
- 非今日页右栏仍为空（`app.dart:310-315`）⇒ **不得**在项目页/日历页画一个不会出现的目标按钮（不许假提示）。

### 6.4 周期滚动（系统发动机，GTD 周回顾）

每周生成动作序列（全部**草稿态 `status='draft'` + 需确认**）：
1. 取本周 `weekly` 目标：未完成（`status != 'done'`）者列为结转候选；
2. 取本周 `review_note` / `improve_note`，作为下周对应候选的默认备注（`improve_note` → 下周 `note`）；
3. 取本月目标中「本周尚无任何 `tracks` 实体」者，作为新周目标候选（对齐链自动补齐）；
4. 用户确认 → 写 `weekly` 行 + `serves`（→ 本月）+ `derives`（→ 上周）。

月、年同理但候选来源为上一层。触发时机 = 用户进入「周」页签且本周尚无 active 目标时**提示**；`period_start` 是判据来源，**不走 `reminder`**（`reminder.target_type` CHECK 4 值不含 goal，扩值需 v4，代价不成比例）。

### 6.5 提醒与到期

周内 `due_date` 的提醒由 app 侧派生渲染（今日页 / 周视图高亮逾期），**不建 `reminder` 行**（同 §6.4 理由）。若产品后续要求「系统级通知」，则需单独裁决 `reminder.target_type` 扩值 = schema v4（本规划明确不在范围内，避免实现批次顺手改 CHECK）。
