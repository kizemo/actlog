# 门禁脚本说明

本目录存放**质量门禁脚本**（G1–G8）。门禁 = 阶段之间的硬闸门，不通过不允许进入下一阶段。

## 铁律：每个门禁脚本必须先证明自己「有牙」

> 没有验证过会咬的检查等于没有检查。

本目录遵守三条硬规则：

1. **故意破坏自测**：每个门禁脚本都要有一份配套的「坏数据样例」，
   用来证明该脚本在数据被破坏时**确实会失败**。
2. **可复现**：坏数据样例由脚本**生成**，而不是手工维护的二进制文件 ——
   否则样例本身会过期骗人。
3. **真数据**：坏样例要基于**真实业务场景**构造（例：把心跳搞成静默、
   把任务重试次数改成 0），而不是随手编的假数据。

## 当前已实现的脚本

### `g3_schema_check.mjs`（Node，不依赖 Dart）

校验 `docs/schema_v1.sql`：
- DDL 全量可执行
- 14 张表齐全且**集合完全一致**
- 关键索引齐全
- `PRAGMA integrity_check` = ok
- 外键已开启
- **CHECK / UNIQUE / FK 约束真的有牙**（插入坏数据必须被拒）

> ⚠️ 这个脚本的第一版有一个真实 bug：UNIQUE 有牙的三项测试全部**假失败**。
> 原因是前面的非法插入都被 CHECK 拒掉了，数据库里从来没留下过合法基线行，
> 所以「重复插入」根本不重复 —— 是测试自己写错了，不是 schema 有问题。
> 现在改为「先插合法基线行，再插重复行」，并加了 `expectSuccess` 辅助函数。
> **教训：写检查脚本时，必须同时验证「坏数据被拒」和「好数据能过」两条路径。**
